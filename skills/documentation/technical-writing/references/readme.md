# README Reference

Write a README for a user who must evaluate, install, and use the project.
Follow the repository's existing structure when it has one.

Include only applicable sections:

1. Project name and one-line purpose.
2. Main capabilities and limits.
3. Requirements and installation.
4. Minimal working example.
5. Common usage.
6. Configuration, with links to detailed reference material.
7. Verification or test commands.
8. Security or operational cautions.
9. Links to deeper documentation and contribution guidance.

Keep the first successful path short. Put advanced configuration after the
minimal example. Do not duplicate complete API or architecture references in
the README. Remove stale commands and claims instead of preserving them as
historical notes.

# ASD-STE100 Writing Rules

Apply these controlled-English rules to technical prose. Preserve exact quoted
text, identifiers, API names, and repository terminology when a rule would
change their meaning.

## Words

- Use approved simple words, established technical nouns, and established
  technical verbs.
- Use one word for one meaning. Do not alternate synonyms for variety.
- Use each word as one part of speech when practical.
- Use American English unless the repository requires another variant.
- Define an abbreviation at first use. Avoid an abbreviation that appears only
  once.

## Nouns and verbs

- Keep noun clusters to three words or fewer when practical.
- Use hyphens when words form one modifier and ambiguity is possible.
- Use active voice for system behavior and instructions.
- Use simple present tense for descriptions.
- Use imperative mood for instructions.
- Name the actor when the actor matters.

## Sentences and paragraphs

- Write one main idea in each sentence.
- Keep procedural sentences at 20 words or fewer when practical.
- Put one instruction in each procedural step unless actions occur at the same
  time.
- Use vertical lists for sequences and parallel information.
- Keep paragraphs short and focused on one topic.
- Put conditions before actions when the condition controls the action.

## Clarity

- Use positive instructions. State the required action.
- Use concrete nouns instead of vague references such as “this” or “it” when
  the reference can be unclear.
- Avoid jargon, idioms, humor, and promotional language.
- Preserve exact numbers, units, commands, paths, and error messages.
- Use tables only when readers must compare values across the same fields.

## Safety instructions

- Use `Warning` for risk of injury or severe data loss.
- Use `Caution` for risk of equipment, software, or recoverable data damage.
- State the prohibited or required action first.
- State the possible result and the prevention action.

## Exceptions

Accuracy has priority over controlled vocabulary. Do not simplify a technical
term when simplification changes its meaning. Do not rewrite quotations or
public interface identifiers to satisfy these rules.
